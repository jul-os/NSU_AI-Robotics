Задача: Реализация B+-дерева с поддержкой удаления, дискового хранения и
журналирования

Условие:
Необходимо разработать реализацию B+-дерева — самобалансирующейся структуры
данных, оптимизированной для систем с блочным доступом (например, баз данных или
файловых систем). B+-дерево должно поддерживать полный набор операций с учётом
дискового хранения, устойчивости к сбоям и конкурентного доступа. Требуется
реализовать:

1. Операции с деревом:
- Поиск (Search): Найти значение по ключу
- Вставка (Insert): Добавить пару ключ-значение с балансировкой при
переполнении узлов (разделение).
- Удаление (Delete): Удалить ключ с балансировкой при недостаточном
заполнении (заимствование или слияние).
- Диапазонный запрос (Range Query): Вернуть значения для ключей в
диапазоне [min_key, max_key], используя связи между листовыми узлами.

2. Дисковое хранение:
- Хранить узлы в файле с фиксированным размером блока (4096 байт),
используя отображение в память.
- Заменить указатели на индексы блоков, поддерживать структуру дерева на
диске.

3. Журналирование (Write-Ahead Logging, WAL):
- Перед изменением дерева записывать операции в лог-файл для обеспечения
восстановления после сбоя.
- Гарантировать согласованность данных с помощью синхронизации (fsync).
4. Конкурентный доступ:
- Реализовать read-write locks для каждого узла для поддержки параллельного
доступа.
- Обеспечить атомарность операций с помощью мьютексов для WAL.

Требования:
• Параметр порядка дерева (t) задаётся при создании (минимальная степень, где
каждый узел, кроме корня, имеет от t-1 до 2t-1 ключей).
• Все значения хранятся в листовых узлах, внутренние узлы содержат только ключи
для навигации.
• Листовые узлы связаны в двусвязный список для range queries.
• Узлы хранятся в файле с размером блока 4096 байт.
• Журнал записывает операции в текстовом или бинарном формате.
• Использовать язык C и POSIX-стандарт для работы с потоками (pthread) и
файловыми операциями (mmap, fsync).
• Обеспечить корректное управление памятью и освобождение ресурсов.

Входные данные:
• Порядок дерева t (например, t = 3).
• Имена файлов: файл данных (tree.dat) и файл журнала (wal.log).
• Последовательность операций: вставка (ключ, значение), удаление (ключ), поиск
(ключ), запрос диапазона (min_key, max_key).

Выходные данные:
• Результаты операций:
- Поиск: значение или "не найдено".
- Вставка/удаление: подтверждение успеха или ошибка.
- Диапазон: список значений в заданном интервале.
• Состояние дерева после операций (опционально, для отладки).
• Восстановленное дерево из журнала при запуске после сбоя.

Ограничения:
• Ключи и значения: 32-битные целые числа (int).
• Порядок дерева: t ≥ 2.
• Размер блока: 4096 байт (стандартный размер страницы).
• Максимальное количество потоков: задаётся пользователем (например, 4).


Пример выполнения:
1. Создать B+-дерево с t = 3, файлами tree.dat и wal.log.
2. Вставить пары: (1, 10), (3, 30), (2, 20), (4, 40), (5, 50).
3. Поиск ключа 3 → 30.
4. Запрос диапазона [2, 4] → [20, 30, 40].
5. Удалить ключ 3 → запись в WAL, обновление tree.dat.
6. Поиск ключа 3 → "не найдено".
7. Симулировать сбой и восстановить дерево из wal.log.

Источники:

1. B+-деревья:
- Bayer, R., & McCreight, E. "Organization and Maintenance of Large Ordered
Indexes" (Acta Informatica, 1972) DOI:10.1007/BF00288683 — оригинальная
работа по B-деревьям.
- Comer, D. "The Ubiquitous B-Tree" (ACM Computing Surveys, 1979)
DOI:10.1145/356770.356776 — описание B+-деревьев и их применения.
- Cormen, T. H., et al. "Introduction to Algorithms", 3rd Edition, Chapter 18 (MIT
Press, 2009) — классическое изложение B-деревьев.

2. Дисковое хранение:
- Silberschatz, A., Korth, H. F., & Sudarshan, S. "Database System Concepts", 6th
Edition, Chapter 12 (McGraw-Hill, 2010) — принципы хранения деревьев в
базах данных.
- IEEE Std 1003.1-2017, "POSIX Programmers Manual" mmap — стандарт
POSIX для отображения файлов в память.

3. Журналирование:
- Gray, J., & Reuter, A. "Transaction Processing: Concepts and Techniques",
Chapter 7 (Morgan Kaufmann, 1993) — основы WAL и восстановления.
- Mohan, C., et al. "ARIES: A Transaction Recovery Method" (ACM TODS, 1992) DOI:10.1145/128765.128770 — классическая работа по журналированию в
базах данных.

4. Конкурентный доступ:
- Lehman, P. L., & Yao, S. B. "Efficient Locking for Concurrent Operations on B-
Trees" (ACM Transactions on Database Systems, 1981) DOI:10.1145/319628.319654 — алгоритмы конкурентности для B-деревьев.
- IEEE Std 1003.1-2017 pthread_rwlock — стандарт POSIX для блокировок.

Дополнительно (опционально):
• Реализовать восстановление дерева из WAL при запуске.
• Добавить кэширование блоков в памяти для повышения производительности.
• Оптимизировать для современных накопителей (SSD), минимизируя вызовы fsync.
Примечания:
• Реализация должна быть устойчивой к сбоям: после сбоя дерево должно
восстанавливаться до последнего согласованного состояния.
• Балансировка при удалении требует сложной логики заимствования или слияния
узлов, что делает задачу нетривиальной.
